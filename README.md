# Прогнозирование кредитного дефолта

Проект оценивает вероятность дефолта заемщика по данным о кредите и кредитной истории. Итоговая модель — стекинг логистической регрессии и LightGBM с метамоделью Random Forest — повышает ROC-AUC с **0.7466 до 0.7751** относительно baseline CatBoost и лучше обнаруживает класс дефолта.

## Задача и ценность

Пропуск дефолтного заемщика может обернуться финансовыми потерями, а чрезмерно строгий скоринг — отказом надежным клиентам. Модель помогает разделять заявки по риску, учитывая оба класса, а не только общую долю верных прогнозов. Это аналитический прототип, а не готовая система автоматического одобрения кредитов.

## Данные

Исходные CSV взяты с Kaggle и находятся в `data/raw/`:

- `train.csv` — 7 500 строк, 16 признаков и целевой столбец `Credit Default`;
- `test.csv` — 2 500 строк, 16 признаков, без целевого столбца;
- в обучающей выборке 5 387 примеров класса `0` и 2 113 класса `1`, поэтому классы несбалансированы;
- среди признаков есть числовые и категориальные данные, пропуски и аномальные значения.

## Подходы

В ноутбуках исследованы данные и признаки, сравнены baseline и несколько классификаторов. Для baseline использован CatBoost; итоговый вариант — стекинг:

1. Предобработка нормализует отдельные категории, обрабатывает аномальные значения и пропуски. Для восстановления пропусков обучаются CatBoost-модели.
2. Создаются признаки на основе соотношений дохода, долга, платежей и кредитных лимитов.
3. Логистическая регрессия и LightGBM формируют out-of-fold вероятности; Random Forest обучается на этих вероятностях как метамодель.
4. Параметры моделей подбираются с помощью Optuna. Для оценки учитываются метрики обоих классов, в том числе precision, recall и F1, а также ROC-AUC.

Такое сочетание использует разные свойства базовых алгоритмов: логистическая регрессия дает линейную оценку, LightGBM улавливает нелинейные зависимости, а Random Forest объединяет их прогнозы. При дисбалансе классов одной accuracy недостаточно: важно отдельно оценивать пропуски дефолтов и ошибочные отказы.

## Результаты

Метрики рассчитаны на holdout-части обучающей выборки: `train_test_split(test_size=0.25, random_state=42)`, 1 875 наблюдений. Класс `1` соответствует дефолту.

| Метрика | Baseline: CatBoost, класс 0 | Итоговая модель, класс 0 | Baseline: CatBoost, класс 1 | Итоговая модель, класс 1 |
|---|---:|---:|---:|---:|
| Precision | 0.7588 | 0.8234 | 0.8125 | 0.5162 |
| Recall | 0.9726 | 0.7494 | 0.2776 | 0.6246 |
| F1 | 0.8525 | 0.7847 | 0.4138 | 0.5652 |

| Общая метрика | Baseline | Итоговая модель |
|---|---:|---:|
| Accuracy | 0.7643 | 0.7120 |
| Macro F1 | 0.6331 | 0.6750 |
| ROC-AUC | 0.7466 | 0.7751 |

Итоговая модель лучше выявляет дефолты: recall класса `1` вырос с 0.2776 до 0.6246, а его F1 — с 0.4138 до 0.5652. При этом precision этого класса снизился, то есть модель чаще помечает недефолтных клиентов как рискованных. Для класса `0` precision вырос, но recall и F1 снизились; accuracy также стала ниже. Таким образом, стекинг улучшает баланс классов и ранжирование по ROC-AUC, но не превосходит baseline по каждой метрике — выбор подходит, если важнее не пропускать дефолты.

## Запуск

Из корня репозитория установите зависимости и запустите программу:

```bash
python -m pip install -r requirements.txt
python main.py
```

Скрипт загружает `data/raw/test.csv` и сохраненный пайплайн `models/final_pipeline.joblib`, затем записывает прогнозы в `result.csv`. Файл результата создается заново; он содержит столбец `Credit Default` и индекс строк.

## Структура репозитория

```text

|-- configs/
|   |-- model_config.json       # параметры подбора моделей и импьютеров
|-- data/
|   └── raw/                    # исходные train.csv и test.csv
|-- models/
|   └── final_pipeline.joblib   # сохраненный итоговый пайплайн
|-- notebooks/
|   |-- eda.ipynb               # исследовательский анализ данных
|   |-- feature_research.ipynb  # исследование признаков
|   |-- model_selection.ipynb   # сравнение моделей и сборка стекинга
|-- src/
|   |-- transformers.py         # очистка, импьютация, генерация признаков и стекинг
|   |-- utils.py                # оценка и визуализация метрик
|-- main.py                     # запуск прогнозирования
|-- requirements.txt            # зависимости проекта
|-- result.csv                  # результат последнего запуска
```

## Ограничения

- Метрики приведены для случайного holdout-разбиения обучающих данных; отдельная временная или внешняя валидация не проводилась.
- Метрики зависят от порога классификации и соотношения стоимости пропущенного дефолта и ошибочного отказа. Текущий запуск использует порог по умолчанию модели.
- `test.csv` не содержит меток, поэтому качество на нем этой программой не измеряется.
- Перед применением для кредитных решений потребуются проверка качества на актуальных данных, калибровка порога, анализ смещений и контроль требований к обработке персональных данных.
